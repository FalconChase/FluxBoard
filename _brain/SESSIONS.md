## SES011 — 2026-09-03 — Milestone 3 implemented (full node registry)
Progress made    : Implemented the remaining node kinds — `distributor` (roundRobin default / broadcast mode, round-robins across active output edges in port order or copies onto all of them), `sorter` (strict first-match `rules` -> `outputPort`, `defaultPort` fallback, `unmatchedPolicy` 'hold'/'drop' — resolves FBP003 by treating a matched-but-gated-off edge the same as unmatched rather than force-through), `mixer` (per-input-port buffered recipe matching — `recipe: {port: itemType}`, fires only once every port has a matching item queued AND the output edge is active, checking output availability BEFORE consuming any input so a complete-but-blocked recipe just waits instead of destroying items), and `buffer`/overflow (capacity-limited queue, `overflowPolicy` 'block' (accepted:false backpressure, default) or 'divert' (bypass straight to an overflow edge), continuous one-item-per-tick `tryDrain`). Extended the shared contract in `src/core/nodes/contract.ts`: `OnItemArrivalResult.accepted?` (false = refuse this arrival, item stays parked at progress 1 and is retried next tick — the general backpressure mechanism used by sorter/mixer/buffer), a new `'forward'` Action type (distinct from `'send'`) so a forwarded/copied item is tracked as a `forwarded` SimEvent rather than double-counted as a fresh `spawned` one, `OnItemArrival` now also receives the arriving `EdgeDef` (for `arrivalEdge.targetPort`, needed by the mixer) and a `makeItemId` callback (needed by distributor's broadcast copies and the mixer's recipe output), and a generalized `PerTickHook` type shared by source's `trySpawn` and buffer's `tryDrain`. Split `src/core/nodes/index.ts` into per-kind files (`contract.ts`, `source.ts`, `sink.ts`, `distributor.ts`, `sorter.ts`, `mixer.ts`, `buffer.ts`) with `index.ts` reduced to assembling the `nodeHandlers` registry. `SimEngine.deliverArrivals` now respects `accepted: false`, and its per-tick loop (renamed `runPerTickHooks`) calls both `trySpawn` and `tryDrain` where a node kind defines them. Added `src/core/__tests__/nodeRegistry.test.ts` — 25 new cases, mostly unit tests calling each node's `onItemArrival`/`tryDrain` handler directly (precise control over state/edges, no tick-timing choreography) plus a handful of SimEngine-level integration tests (FBP003 end-to-end, item conservation through a source->buffer->sink graph, round-robin end-to-end balance). `npx tsc --noEmit` clean; could not run `npm test` from the bridge VM this session (node_modules still built for Windows from Falcon's last local `npm install`, same as SES009/SES010 — verified by hand-tracing the tick math for the timing-sensitive tests instead, per the established pattern) — Falcon to confirm with `npm test` locally. Still schematic rendering only, as discussed with Falcon before starting (confirmed acceptable — "the app will look like a software" comes from Milestones 4 and 5 together, not this one).
